# TimesFM 在金融领域的应用总结

## 核心问题：TimesFM 能否直接用于金融预测？

**答案**：❌ **不能直接使用** | ✅ **需要微调后可用**

---

## TimesFM 的基本情况

**模型信息**：
- 来源：Google Research (github.com/google-research/timesfm)
- 版本：v2.5 (2025年9月)
- 大小：200M 参数 (从v2.0的500M缩减)
- 上下文窗口：16k tokens (从2048扩展)
- 预训练数据：1000亿个时间序列数据点

**核心能力**：
- 点预测（均值预测）
- 分位数预测（10-90百分位数，用于不确定性估计）
- 可变长输入/输出
- 批量处理

---

## 为什么预训练的 TimesFM 在金融数据上失败？

研究发现：Preferred Networks & Google Research 的结论是基础 TimesFM **"在价格预测上表现很差"**

**原因**：
1. 预训练数据是**通用时间序列**，不是财务特定的
2. 金融数据有独特的特性：
   - 高价股票会主导损失函数（高数值偏差）
   - 市场崩盘时价格可能下跌 >99%，训练不稳定

---

## 解决方案：对数变换微调

### 关键改进

**损失函数应用对数变换**：
```python
# 而不是：MSE(y_pred, y_true)
# 应该是：MSE(log(y_pred), log(y_true))

loss = MSE(log(predicted_prices), log(actual_prices))
```

**好处**：
- ✅ 防止高价股主导训练
- ✅ 稳定极端市场事件的训练
- ✅ 对OHLC各分量分别应用

### 微调配方

```
数据：79,153+ 小时/日频时间序列（股票、加密、外汇、商品）
上下文：512 时间点
预测范围：128 时间点
硬件：8 块 V100 GPU (~1小时训练)
优化器：SGD, LR=5e-4, 100 epochs (warmup + cosine衰减)
```

---

## 微调后的性能

### 市场中立策略回测结果

| 市场 | Sharpe比率 | 年回报率 | 最大交易成本 |
|------|-----------|--------|-----------|
| 标普500 | **1.68** ✅ | 3.6% | 0.60% |
| TOPIX 500 | 1.06 | - | - |
| 加密货币 | ❌ 差 | - | 需域名适配 |
| 外汇 | ❌ 差 | - | 需域名适配 |

**关键指标**：
- 比基础TimesFM性能更好
- 比随机预测好
- 但在加密/外汇上不如AR(1)自回归基线（需要特殊改进）

## TimesFM vs Kronos 对比

### 架构对比

| 特性 | Kronos | TimesFM |
|------|--------|---------|
| 参数量 | 4.1M-102.3M | 200M |
| 架构 | 分层token (s1/s2) | 解码器transformer |
| 上下文窗口 | 512 | 512+ |
| 时间特征 | 显式 (分钟/小时/周) | 隐式 (依赖数据) |
| 预测类型 | 点预测 | 点+分位数 |
| K线特化 | ✅ 高度优化 | ✅ 通过微调 |
| 不确定性 | ❌ 无 | ✅ 有分位数 |
| 计算成本 | 低-中 | 中 |

## 在 Kronos 中集成 TimesFM 的方案

### 推荐方案：多模型集成

```
用户请求
  ├→ Kronos（短期，K线优化）
  ├→ TimesFM（中期，不确定性感知）
  └→ 集成聚合 → 最终预测 + 置信度
```

**优势**：
1. 不同架构的归纳偏差可以降低预测方差
2. TimesFM的分位数输出提供风险量化
3. 覆盖短期和中期预测

### 其他方案

**方案2**：资产类别路由
- 股票（高频/短期）→ Kronos
- 加密/外汇（中期/多资产）→ TimesFM

**方案3**：备份/比较策略
- 主要：Kronos
- 备用：TimesFM（如果Kronos置信度低）
- 监控：对比检测模型漂移

---

## 集成 TimesFM 的挑战

### ⚠️ 主要挑战

1. **必须微调**
   - 不能直接用预训练模型
   - 需要80K+金融时间序列
   - 需要8个V100 GPU和~1小时

2. **不同的数据管道**
   - 对数变换（vs Kronos的标准化）
   - 不同的特征工程策略
   - 不同的损失函数

3. **在加密/外汇上表现差**
   - 需要额外的域名适配
   - 不是开箱即用

4. **部署成本**
   - 200M参数模型（vs Kronos的4-100M）
   - 内存和延迟影响

## 何时值得集成？

### ✅ 应该集成

- 您的应用需要**不确定性量化**（分位数预测）
- 想要**多模型集成**以提高鲁棒性
- 有**足够的计算资源**进行微调
- 涉及**多资产类别**（股票+加密+外汇）

### ❌ 不必集成

- 只关心**点预测**，不需要不确定性
- Kronos性能**已满足要求**
- **计算资源有限**
- 只在**高频/短期**交易（Kronos已优化）
